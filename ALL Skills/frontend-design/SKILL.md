# 有明确方向的 Web 设计

来源与适配差异见 [ORIGIN.md](ORIGIN.md)。

## 依据真实内容设计
阅读用户的视觉要求、品牌、参考图和页面目的。用户明确指定的风格优先，不能因为某风格流行就强行避开，也不能把某套配色、字体或卡片风格套到每个项目。
识别页面的主要动作与信息层级。保留已有内容、链接和业务功能；不要为了美化杜撰经营数据、评价、价格或承诺。

## 先定简短视觉方案
确定少量颜色令牌、字体角色、字号层级、容器宽度、间距和一个主要记忆点。用现有字体或用户允许的来源，不在技能包里分发字体文件。
首屏围绕主题选用标题、图像、演示或交互。文字、边框、编号、标签和卡片必须表达信息，不能只为“看起来设计过”。

## 实现
沿用项目框架、组件与样式系统，避免叠加另一套 UI 库。实现真实移动端与桌面布局，检查长中文、长链接、极少/极多内容和空状态。
动效服务于反馈或一个明确的叙事重点，尊重减少动态效果偏好。按钮文案说明具体动作；错误说明原因和处理办法，不只显示失败。
图片素材需要真实生成或取得授权；缺素材时清楚标记，不把占位当成成品。

## 视觉验收
实际打开页面，在至少一个窄屏和一个桌面宽度下截图。检查层级、对齐、留白、换行、裁切、滚动、遮挡、对比度、焦点和可点击状态。
对照参考逐项修正；只看源码不能声称视觉验收通过。可结合 `web-design-guidelines` 和 `webapp-testing`。

## 交付
说明主要视觉变化、保留的功能、实际截图/预览、已验证尺寸及未完成项。不要长篇解释审美口号。
