# 对实际改动做代码审查

来源与适配差异见 [ORIGIN.md](ORIGIN.md)。本版允许单代理自查，不强制安装子代理。

## 明确审查对象
读取需求、相关文件和实际差异。检查已提交差异、暂存区与未暂存改动；相关新文件也要读。不能只看 HEAD~1 到 HEAD 而遗漏尚未提交的工作，也不要为了审查执行 git add/commit。
若基线不明，先依据项目历史确定合理范围并注明；不要审查整个仓库代替用户指定范围。

## 选择执行方式
有可靠的独立审查代理时，仅提供需求、范围、基线/当前版本与关键测试信息，不共享不必要的会话历史和秘密。没有时自己审查，并标明“单代理自查”；不要假装有第二位审查者。

## 检查重点
关注可证实的正确性、边界、数据丢失、权限、输入校验、资源泄漏、异常处理、并发、回归、兼容性和测试空白。涉及 UI 时补交互与响应式。风格偏好不能包装成严重缺陷。
阅读受影响调用方与上下文，确认问题可发生；不要只依据 lint 或模型直觉报错。

## 每条发现
给出严重程度、文件与行号、触发条件、实际影响、最小修复建议和验证办法。区分证实问题、待验证风险、一般建议。无法运行测试时明确说明。

## 审查后
优先解决阻断问题，重新运行相关验证。对争议项用代码或测试证据解释，不一概接受也不无视。未发现问题时说明审查范围和剩余风险，不声称绝对安全。
