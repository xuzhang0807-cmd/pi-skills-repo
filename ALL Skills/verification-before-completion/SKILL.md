# 用证据验收

来源与适配差异见 [ORIGIN.md](ORIGIN.md)。

每次准备说“完成、通过、已修好、已部署”时：
1. 明确哪项观察或命令能证明这个具体结论。
2. 运行适合当前改动的真实验证，记录使用的版本/路径和命令。
3. 阅读退出码与完整相关输出，不只搜到 PASS 就忽略其他错误。
4. 将结果标为通过、失败或未验证，再写结论。

## 不可互相替代的证据
- lint 通过不等于构建通过；构建通过不等于网页能打开。
- 一个测试文件通过不等于整套测试通过。
- 容器启动不等于用户入口和数据库都正常。
- 文件存在不等于文件能被正确打开、渲染或播放。
- 模型、子代理或外部任务说成功不等于已核验实际产物。
- 生成提示词不等于图片或视频已经生成。

## 执行要求
依照项目现有脚本选择检查。大量测试受时间、费用或权限限制时，说明已覆盖与未覆盖范围，不能把抽检写成全检。已有失败也应列出，区分新引入与原有问题。
不要为满足验证仪式而删除用户工作、修改生产数据、安装不明程序或执行高风险命令。无法安全验证就报告限制。

## 交付格式
```text
结论：通过 / 部分通过 / 失败 / 未验证
产物或版本：...
验证：命令或检查项 → 实际结果
未验证/失败：...
下一步必要动作：...
```
只保留与本次任务有关的项目，避免大段模板。
