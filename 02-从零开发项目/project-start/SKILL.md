# 从需求到可运行项目

本技能为本次本地新编，非第三方仓库原版。来源说明见 [ORIGIN.md](ORIGIN.md)。

## 确定最小交付
阅读已有文件，包括隐藏文件。已有项目先理解再扩展，不覆盖 `.git`、`.env` 或其他有效内容。
从用户信息确定：目标用户、核心功能、输入输出、运行位置、数据存储、部署与验收标准。已有答案不重复询问；非关键空缺用明确、可撤回的假设推进。涉及账号、费用、隐私或不可逆决策时获取必要授权。

## 选择实现
优先复用现有技术栈、组件和官方脚手架。只为当前最小产品增加依赖，不默认微服务、复杂调度、多种数据库或整套插件。需要当前版本/API 时核对官方文档。
先做一条端到端可运行路径，再扩展功能。将计划拆成少量任务，每项有文件范围、可观察验收和依赖；大型项目记录到项目文档，短任务不强制新建一堆文件。

## 实现闭环
1. 准备目录与最小启动入口，沿用锁文件和包管理器；新增依赖说明用途。
2. 为关键行为建立测试；用 `test-driven-development` 处理功能与缺陷。
3. 实现输入校验、错误和空状态；账号、权限、文件上传和数据写入必须明确边界。
4. 涉及 UI 时使用 `frontend-design`，保留移动端、键盘操作和加载状态。
5. 运行真实项目；网页用 `webapp-testing`，代码用 `requesting-code-review`。
6. 使用 `verification-before-completion` 核验交付。

## 交付最少但完整
提供已实现功能、实际运行命令、配置项名称、测试结果和剩余限制。使用 `.env.example` 记录名称与说明，不写真实密钥。
需要部署时再使用部署场景，不把“本地启动了”当作上线。不要自动提交、推送、创建远程资源或变更用户全局配置。
