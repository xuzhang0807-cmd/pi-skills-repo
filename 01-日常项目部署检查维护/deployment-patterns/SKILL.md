# 部署与回滚

这是按上游原则重写的轻量适配版，来源与差异见 [ORIGIN.md](ORIGIN.md)。

## 先确认边界
读取项目 README、部署说明、锁文件、容器与 CI 配置。确认目标是本地、测试还是生产，识别实际服务名、工作目录、端口和持久化数据。沿用已有架构；单机服务不要为了套模板引入集群。
用户只要求检查时，不发布、不重启、不修改 DNS 或防火墙。不读取或输出密钥正文；只报告变量是否存在及配置位置。对生产发布、不可逆迁移、付费资源、数据删除，执行前说明具体影响并取得相应授权。

## 工作流
1. **只读预检**：检查工作区差异、分支/提交、运行状态、近期错误、磁盘与资源、依赖和环境变量名称。用真实结果建立基线，不把示例命令当成已执行。
2. **选择发布方式**：根据实例数、可接受中断、资源和风险选择原地、滚动、蓝绿或灰度。单实例更新可能中断，不承诺零停机。先报告将变更的文件、服务和版本。
3. **建立回滚点**：记录当前镜像摘要或产物、配置版本、数据备份位置与恢复验证方式。迁移采用可兼容旧应用的分阶段方案；明确哪些变化不能靠旧镜像撤回。
4. **验证后发布**：先运行项目实际测试和构建；优先测试环境。变更保持最小，使用项目已有部署入口；缺少权限或工具就停在可验证的准备阶段。
5. **上线验收**：检查进程、内部健康端点、用户实际入口、核心读写链路和近期错误。外部依赖故障不要一律变成应用存活失败而导致反复重启。
6. **出现异常**：按事先定义的阈值停止推广；只在回滚条件明确、数据兼容且授权范围内回滚。保留日志和失败现场。

## 特别注意
数据库迁移状态标记不是数据回滚。不能把 `prisma migrate resolve --rolled-back` 当成撤销已执行 SQL 或恢复数据。涉及具体数据库或云平台时先核对其当前官方说明。
不得把 `echo Deploying...`、CI 任务开始或命令提交成功作为发布成功证据。不要自动执行 Git 提交、推送或全局软件安装。

## 交付
给出：目标环境与版本、执行了什么、验证证据、未验证项、回滚入口。存在失败或未确认项时，不写“全部完成”。
